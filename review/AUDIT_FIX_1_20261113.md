# Audit repair 1: dice validation and search focus

Candidate: 20261113-r1. Public fixtures only; no custody or beta approval.

The Dice converter previously kept a successful comparison after Undo removed
one roll and the generated words disappeared. It now invalidates comparison
messages when rolls, pasted bits or comparison words change. Pending or invalid
binary input cannot be compared to an older set of displayed words. Clear and
Lock and clear cancel pending input processing. Word derivation, checksum code
and the OS-managed public-test gate are unchanged.

Search previously let Shift+Tab move behind its open dialog. It now wraps
keyboard focus over the currently available controls, makes background siblings
inert, and restores their prior inert state and the opener on close. This covers
loading, failed search-index loading, results, and no-match fallback links.

## Automated evidence

- `node scripts/test_dice_validation.cjs`: shipped inline code and crypto with DOM doubles.
- `node scripts/test_search_focus.cjs`: shipped search controller with DOM doubles.
- Both regressions fail against the original source and pass against the repair.
- Existing network/session and cryptographic checks are retained in CI.
- These checks do not establish real-browser accessibility or physical Tails behavior.

## Browser observation

Cloud Chrome, local HTTP preview: search focus wrapped from the input to the
last result and back, and Escape restored focus to the search button. Repeated
on the one-key route with no-result fallback links. Background content was
absent from the open dialog accessibility tree and returned after closing.
This is not physical Tails, Windows, mobile or screen-reader certification.
Dice local-file behavior still needs the target-environment retest below.

## Manual review still required

One action at a time. State the expected result, receive a non-secret photo,
state what it proves and what remains unverified, then provide a filename.
Save the native screenshot in one Evidence folder on the data USB before the
next action. Keep its actual `.png` or `.jpg` extension. On Tails 7.16, use
**Open in Console**. Run the package verifiers before the following checks.

1. In the local Dice converter, unlock with the two acknowledgments after OS
   networking checks. Use public test rolls and copy the resulting public words
   into Validate. Check: comparison passes. Suggested stem:
   `T5-dice-validation-public-match`.
2. Click Undo. Check: incomplete words and previous validation disappear.
   Suggested stem: `T5-dice-validation-undo-cleared`.
3. Generate and validate the public fixture again, then change a word in the
   comparison input. Check: previous result disappears immediately.
   Suggested stem: `T5-dice-validation-edit-cleared`.
4. Repeat using supplied binary fixtures. Check that editing bits clears the
   result immediately, an early validation cannot compare the old words, and
   Clear/Lock and clear do not let pending processing restore output.
   Suggested stem: `T5-dice-validation-paste-cleared`.
5. Open Ask the guide. Press Shift+Tab from the search box. Check: focus remains
   inside the dialog, on its last available link (or input while loading).
   Tab from the last link returns to the search box. Suggested stem:
   `search-keyboard-focus-contained`.
6. Press Escape. Check: dialog closes and focus returns to the control used to
   open it. Repeat for no results and both guide paths. Suggested stem:
   `search-keyboard-focus-restored`.

A still photo cannot prove the full keyboard sequence or clipboard/memory
clearing. Record the tester's observation and browser/OS alongside each image;
use a non-secret recording if needed. Do not upgrade those limits into a pass.
