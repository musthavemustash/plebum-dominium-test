Doing the T6 rehearsal?

Start with the complete offline tester and follow the T6 checklist. Save the T6 run sheet. Use a new disposable one-key wallet, paper records and test-network coins. Keep any existing wallet outside this exercise.

Before creating the practice wallet, select and record the exact test network supported by your verified wallet software. The offline signer, online watch-only wallet, faucet, server and explorer must all use that network. If it is unclear, stop and record the blocked step. Keep the signing session offline.

The later metal and optional hardware stages in the general guide are outside this rehearsal.

Finish the one-key and passphrase plan without risking your only working wallet.

1. Assess the existing wallet

If funds are on an exchange, you may not control its signing keys. If a seed may be exposed, plan a move to a newly generated wallet. Preserve the old working signer and records until the transfer and recovery checks are complete. Do not overwrite its seed in place.

2. Understand the passphrase

Adding a passphrase selects a separate wallet. It does not move existing funds or protect coins left in the previous wallet. Use a strong independently generated passphrase, record it exactly and keep durable backups separate from the seed. Check the wallet software’s passphrase support and record every character exactly. A missing or mistyped passphrase can open a different, empty wallet without an error.

Use the Diceware mapper

Enter each five-dice group to look up its word. This creates passphrase words, separate from the 24 seed words made by the dice converter.

  2. Complete all six example groups from the mapper retest instructions. Check each word against the saved EFF wordlist.
  3. Compare the copied text, including spaces and spelling, then Lock and clear. Return to this guide tab to continue.

Practice words are public test data. They must never protect real funds. The mapper supplies no computer-generated rolls.

Use the exact package and fingerprints listed on Downloads. The November 13 candidate changes dice-validation behavior and needs its own affected checks. Earlier R3 results apply only to that recorded package and scope. Use public fixtures and disposable test passwords only; real-wallet use remains outside this release.

3. Set up the offline software wallet

Verify Tails and the wallet software before disconnecting. Start Tails in Offline Mode and use the one-key generation guide after its prerequisites and input-method checks pass. In Sparrow, create a Single Signature wallet and import the checked BIP39 seed through New or Imported Software Wallet. Enable the wallet passphrase and enter the exact separately recorded test passphrase before recording the wallet’s public details. Record the network, script type, account, derivation path and several full receive addresses for comparison during recovery. Enter secrets only in verified offline wallet software, never in this site, a connected computer or a support form. Do not save a wallet containing secrets to persistent storage or a transfer USB. Keep the online wallet watch-only.

4. Verify recovery before funding

For T6: use the disposable seed backup on paper and the separately recorded exact test passphrase. Read every entry back. Metal transfer is a later stage and is outside T6. In a fresh offline Tails session, restore from these records and the saved wallet settings. Compare several full receive addresses with the independently checked records. Keep the originals intact; do not wipe your only working wallet to test an unproven backup. Investigate unexpected addresses or balances without destroying the original records. See backup checks.

5. Receive and sign a test transaction

Use disposable keys and the designated test network only during public-alpha testing. Export public information to the online watch-only wallet. Compare its full receive address with the checked offline wallet before receiving test coins. Create an unsigned transaction (PSBT) online. Review the network, recipient, amount, total fee and every change output in offline Sparrow, then sign with the restored key and exact passphrase. Export only the signed transaction, shut Tails down fully, and broadcast from the online wallet. Confirm receipt and rehearse another spend after restoration. Do not use real funds in this test.

6. Keep the plan maintainable

Do not destroy old backups just because one account displays zero; other accounts, pending payments or future incoming transfers may still matter. Document retirement deliberately. A decoy balance is not guaranteed protection under coercion. Prepare a private recovery plan for trusted helpers. Hardware signing is optional: only after the metal backup and recovery checks pass may a compatible device use the existing backed-up key. Do not generate a replacement key on that device. Recovery must still work with offline software.
