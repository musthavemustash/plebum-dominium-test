Understand what the design protects—and what still depends on your equipment and recovery plan.

Does a fresh boot remove every risk?

No. Offline sessions reduce network exposure but do not establish trustworthy hardware or firmware. A persistent compromise can observe keys across different boots on the same computer. One key per boot is not independent hardware isolation.

Are dice automatically trustworthy?

The input must be unpredictable and the conversion correct. Biased rolls, transcription errors or incompatible input methods undermine the result. Observable dice do not eliminate trust in the software that turns rolls into keys.

Can one stolen key spend?

One distinct key cannot satisfy a correctly configured 2-of-3 policy alone. Two compromised signing keys can. Devices containing copies of the same key do not create independent cosigners.

Can I recreate the map from seeds?

Do not rely on that as the backup plan. Preserve verified configuration, including script type, key origins and all cosigner public information. Protect its privacy and test that it restores the intended wallet.

Should every cosigner have a passphrase?

A cosigner passphrase adds a recovery dependency. This guide’s basic three-key route does not require one. Adding any requires documenting exactly which signer uses it and testing the resulting configuration; it is not a substitute for key separation.

What proves the plan works?

Rehearse setup, signing and recovery with disposable test keys, including the intended signer pairs. A matching receive address or a single successful payment is useful evidence, not proof that a coordinator is trustworthy or every backup works.
