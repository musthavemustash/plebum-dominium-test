Build the 2-of-3

Plebum Dominium teaches self-custody without a hardware wallet. Create and verify keys with offline software, put the backups on metal, and check that they restore the intended wallet. Use offline software to sign. Hardware wallets are optional signing tools introduced only after the metal backups are complete and checked.

A 2-of-3 watch-only wallet is built from three public keys. One seed per offline boot supplies each public key. The exported wallet map can reconstruct the wallet’s addresses and watch its transactions; it cannot sign by itself.

Read the structure first. The seven steps below explain the process. Before doing the hands-on rehearsal, continue to Set up a test wallet to select the test network, create disposable keys, and save temporary recovery records. Use that network’s verified settings for practice. This public review uses no real wallet secrets or funds.

Safety first: Never enter seed words on an online computer. You will boot Tails four times: once per seed to copy its public key, then once more with no seed to build the vault.

Recorded walkthrough versions: Sparrow 2.5.5, Tails 7.16 and Electrum 4.8.3. Check current publisher releases and version-specific verification before a new test. Record the actual versions you use; the earlier results do not establish compatibility for a newer release.

How the build works

  1. Boot Tails offline. Launch Sparrow from the terminal.
  2. Extract each seed's public key, one per boot.
  3. Build the 2-of-3 vault with no seed. Export the map.
  4. Independently verify the cosigners and wallet policy, then compare several receiving addresses.

Step 1 / 7

Boot Tails. Networking stays off.

The entire sheet happens with networking Disabled. Check it on every boot.

Step 2 / 7

Open the terminal. Launch Sparrow.

The commands below use the recorded Sparrow 2.5.5 filename. For another verified release, substitute its exact archive filename. Run these commands one at a time. Wait for each command to finish before entering the next. The shell prompt is not part of a command.

cd ~/Desktop
tar -xvf sparrowwallet-2.5.5-x86_64.tar.gz
cd Sparrow
./bin/Sparrow

Sparrow may take 15 to 30 seconds to open. The terminal may remain occupied while Sparrow runs. If a command reports an error or the expected window does not open, stop and investigate; text color alone is not an error check.

Step 3 / 7

New wallet: 2 of 3, native Segwit.

File → New Wallet. Pick Multi Signature, Native Segwit, 2 of 3. Confirm the selected network and the documented derivation settings for every signer before exporting public keys.

Mainnet reference: m/48'/0'/0'/2' is the example path for the intended mainnet setup described here. It is not an instruction to force the practice wallet onto mainnet settings. For the disposable rehearsal, use the selected test network’s documented settings. Do not reuse its keys for the eventual mainnet wallet.

Check: Network, 2-of-3 policy, script type, and derivation settings agree with independently verified signer records. Stop if any setting is unexplained.

Step 4 / 7

Keystore 1: Seed 1 in, public key out.

Keystore 1 → New or Imported Software Wallet → type Seed 1's 24 words. Export the xpub. Save it to the data USB as s1-xpub.txt. Close Sparrow. Shut down. Wait for a dark screen.

Step 5 / 7

Twice more. One seed per boot.

Boot again for Seed 2 → s2-xpub.txt. Shut down. Boot again for Seed 3 → s3-xpub.txt. Shut down.

Check: Three xpub files on the USB. One seed per boot, never two.

Step 6 / 7

Fresh boot. No seed. Build the vault.

Boot Tails again. Do not type any seed. New wallet → Multi Signature → Native Segwit → 2 of 3 → import the three xpub files. Confirm the path. Export the output descriptor to the data USB. That file is the wallet map.

Step 7 / 7 · Before funding

Verify the wallet independently

Matching addresses alone cannot prove a coordinator is honest if both devices use the same unverified descriptor.

  1. 01 · Record addresses

    Record several complete receiving addresses from Sparrow offline. Write the full strings, not just QR codes.

  2. 02 · Verify each cosigner

    On a separate trusted offline device, compare each cosigner’s master fingerprint, derivation path, and extended public key with records obtained directly from that signing session, not solely from the coordinator.

  3. 03 · Check the wallet policy

    Confirm the 2-of-3 threshold, native SegWit script type, and full descriptor including key order and checksum where supported.

  4. 04 · Rebuild and compare

    Reconstruct a watch-only wallet from independently verified details. Compare several receiving addresses character for character. Never enter seeds on a networked device.

Stop before funding if anything differs. If a key, fingerprint, path, policy, or address differs, investigate offline. Two devices using the same substituted descriptor may show matching attacker-controlled addresses.
