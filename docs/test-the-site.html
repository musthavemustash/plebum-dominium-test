Help test the site

Choose a task, check the expected result, and tell us what happened. No Bitcoin experience is required for a reading or navigation review.

Browse and review only. Do not enter real wallet information, connect a wallet, create or fund a wallet, or send funds. Never submit seed phrases, private keys, passwords or wallet backups.

Try a five-second homepage test

Open the version you were sent, look at the first screen for five seconds, then answer these in the form’s description.

  • What did you think this site would help you do?
  • Where would you tap first?

Include the exact homepage link and whether you used a phone or computer. If you’re recruiting testers, alternate versions and send each person just one link.

Useful verification tasks

Try one task or several. Record PASS, FAIL or NOT TESTED; a skipped test is not a pass. Use one form response per task or issue.

Follow a complete path

Try: Choose One key + passphrase or Three keys. Read each page using Next, then check Previous. You do not need to perform the wallet instructions.

Expected: Terms → Before you begin → Pick your path, followed by consecutive steps: 12 for one key, 16 for three keys. No skipped pages or “not on your path” dead ends.

Switch paths

Try: Use the sidebar to switch to the other path. Check the page title, step number and next destination.

Expected: Navigation and consecutive numbering follow the chosen path; the route overview may be unnumbered.

Try the Threat Model worksheet

Try: On Before you begin, select hypothetical security concerns and change the wallet starting point.

Expected: The summary reflects your selections. Explanations are understandable without disclosing your finances.

Check the layout

Try: On a phone, open and close the menu, rotate the screen and expand cards. On desktop, narrow the window and try 200% zoom.

Expected: Readable text and usable controls, with no overlap, clipped content or unnecessary nested scroll boxes.

Use the keyboard

Try: Try Tab, Shift+Tab, Enter, Space and Escape. If you use a screen reader, note confusing control names or reading order.

Expected: Focus stays visible. Controls work without a mouse, and the menu can close without trapping focus.

Try search and Copy

Try: Search for a word you saw on a page, then a nonsense word. Clear the search. Copy a verification command and paste it into a blank text editor only—do not execute it.

Expected: Results and no-results messages make sense; clearing works. Copy feedback is clear and the pasted text matches the displayed command.

Review an explanation

Try: Identify a confusing term, missing prerequisite, contradictory instruction or claim that needs evidence. Include a short quotation and page link.

Expected: A reader can understand the next step and its purpose. Report possible safety errors even if you are unsure how to fix them.

Make your result useful

In the form’s description, include these details. Successful tests help us track coverage too.

  • Task performed and PASS / FAIL / NOT TESTED.
  • Exact page link and chosen path.
  • Device, browser and test date.
  • Steps you took, expected result and actual result.
  • Where you stopped, and whether you can repeat the issue.

Example: “FAIL — keyboard task. Three keys, Before you begin [page link]. Firefox on Windows, November 4. Opened the menu, pressed Escape; expected it to close, but it stayed open. Repeated twice.” This is an illustrative report, not a known current bug.

The form does not accept file uploads. If you send a screenshot separately to the project owner, remove personal information and unrelated tabs. Contact details in the form are optional; response summaries are not public.

Help test the download release

Experienced volunteers can help check the candidate tools in a browser and on physical Tails hardware. Use public fixtures and disposable test data only.

  1. Request the current candidate. Contact the project owner with your device, operating system, browser, and whether you can test physical Tails. Request the candidate version, file fingerprints, public fixtures, expected outputs, and assigned checks. Older shared ZIPs contain outdated instructions and may differ from the corrected standalone files.
  2. Identify exactly what you tested. Record the candidate version and file fingerprints supplied with it. If the files differ from the assigned candidate, stop and report the mismatch before testing.
  3. Run the assigned checks. For browser review, check loading, controls, input validation, and outputs against the supplied public fixtures. For physical Tails review, record the Tails version, offline setup, tool startup, fixture results, and behavior after closing the tool and rebooting. Report what you actually observed.
  4. Record each result. Submit PASS, FAIL, or NOT TESTED with the candidate version, device and software versions, steps, expected result, actual result, and whether you reproduced it. Include only public fixture outputs. A skipped test remains NOT TESTED.

Keep wallet seeds, private keys, real entropy, passwords, and wallet backups out of the test and feedback. Request a refreshed candidate instead of using the blocked legacy release.

How your feedback helps

We use exact steps to reproduce problems, prioritize possible safety errors, fix staging, and repeat affected tests. Device details reveal compatibility issues; reviewed-page lists show coverage. Reader feedback supports usability—it does not replace cryptographic checks, physical offline testing or wallet recovery validation.
