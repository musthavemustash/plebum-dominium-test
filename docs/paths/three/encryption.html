Protect the wallet map’s privacy without making recovery depend on an untested file.

Understand the map

A verified public-only descriptor describes the wallet’s scripts, cosigner public keys and derivation information. It can reveal wallet activity but cannot sign by itself. Some exports contain private keys: confirm the export type before treating it as public data.

Keep the complete verified configuration. Do not assume three seeds alone automatically recover every script type, derivation path or wallet setting. Encryption protects confidentiality; it does not replace configuration backups.

Choose a recoverable protection plan

Decide who needs access after loss or incapacity. Keep more than one protected copy, with a durable record of the decryption method and its password or required key. Avoid making every copy depend on one forgotten password.

The file-encryption password is separate from a Bitcoin wallet passphrase and a device PIN. Do not reuse signing secrets as encryption passwords. Arrange separate access to encrypted copies and their unlocking material without making either impossible for your recovery plan.

Encrypt offline using a documented method

Tails includes Kleopatra: select Sign/Encrypt, choose the file, then Encrypt with password for password-based encryption. Use Decrypt/Verify to open the encrypted file. Follow the official Tails instructions for your installed version.

Use an offline session and trusted software. Never enter a real encryption password, private key or seed on this hosted website. A browser’s offline indicator is not proof that the system is isolated.

Verify before replacing any copy

Start with harmless sample text. Test decryption in a later session, using the exact software intended for recovery. For a real map, verify the entire recovered contents against the original before relying on the encrypted copy.

Keep the existing protected backup until these checks pass. Deleting a file or emptying the trash does not prove every copy has been erased. Plan plaintext handling before writing sensitive material to persistent storage.

Keep the existing tool in review

The bundled descriptor tool remains available, but its cross-tool compatibility and offline behavior still need independent testing in this review. Do not use it as your only recovery path or assume its self-reported checks certify it.

No encryption implementation has been changed here. Rehearse with non-sensitive sample data and retain a verified recovery option. The legacy print packet has not yet been reconciled with this guidance.

Pause and check: Stop if decryption fails, the recovered map differs, the export contains unexpected private material, or you cannot explain how a trusted helper would regain access.
