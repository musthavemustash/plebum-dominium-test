PLEBUM DOMINIUM: T7 THREE KEYS / 2-OF-3 REHEARSAL
Live instructions updated November 17, 2026. T7 remains NOT TESTED.
T6 passed; its results improve these directions but do not pass multisig checks.

PREPARE BEFORE GOING OFFLINE
Use the signed complete 20261115-r1 ZIP and its verification files from Downloads.
Verify the signature/checksum, extract fully and run verify_package.py. Prepare
verified Tails and Sparrow separately; record actual versions and exact ZIP hash.
Save this sheet, WALLET-TRANSFER-CHECKS.txt, PHOTO-REVIEW-FLOW.txt and
TAILS-OFFLINE.txt BESIDE the verified extraction. Do not replace package files.
The November 17 notes download contains instructions only, not a signed tool release.

Use Testnet4 explicitly on every wallet, server, faucet and explorer. The T6
walkthrough used Sparrow 2.5.6; T7 compatibility still needs its own evidence.
Create fresh disposable keys A, B and C; do not reuse the T6 key. No BIP39
passphrases are used for this guide's three-key path. A wallet-file password is
separate and does not change that rule. Use TEST ONLY paper records; metal and
hardware signers are outside T7. Never reuse test seeds or dice rolls for real funds.

Keep ONE secret key per offline boot. Keep the online coordinator watch-only.
Never transfer seed words, private keys or a secret-bearing wallet file on the
data USB. Wallets containing secrets stay in temporary Tails Home, persistence off.
On each boot choose Disable all networking, check OS controls and record:
  nmcli -f DEVICE,TYPE,STATE device status
Keep networking off through full shutdown. A Sparrow toggle/browser flag does
not establish OS isolation. Re-extract verified Sparrow into Home as needed;
confirm Testnet4 before importing secrets or opening a transaction. Use a fresh
folder grant to read the guide in Tor Browser; copy/paste the whole helper URL.

ONE ACTION, PHOTO, REVIEW, SAVE
Use PHOTO-REVIEW-FLOW.txt. Review each public result and save the native image
in one Evidence folder before continuing. A separate phone can send review
photos while Tails stays offline. Self-guided testing is valid. Record PASS /
FAIL / NOT TESTED for EACH case; keep warnings and successful retries separately.
Never capture seeds, paper seed records, passphrases or secret QR codes. Record
private steps in writing without secret values. File names are chosen after review.

T7.1 BUILD AND CHECK THE PUBLIC POLICY
Follow the three-key build guide, selecting the test network before key setup.
Use separate offline boots for A, B and C. For each, retain the complete public
origin information: fingerprint, exact account derivation and extended public key.
For the native Segwit multisig Testnet4 account, confirm m/48'/1'/0'/2' against
Sparrow's selected configuration. Do not copy T6's single-key m/84' path or the
mainnet m/48'/0' example. Stop if a setting or software support is unclear.

In a fresh seed-free session, construct the public-only 2-of-3 Native Segwit
(P2WSH) wallet from ALL THREE public records. Check threshold, script, key
origins/order and descriptor checksum against independently obtained signer
records, not merely two windows displaying the same imported descriptor.
Record the first three full receive addresses and first change address.
EXPECT: the complete intended public policy and matching independent records.
Export the complete wallet map with all three public keys and origins, receive
and change information. A single xpub or two seeds alone is not the complete map.

T7.2 CHECK PAPER AND SAVED MAP
Read back each separate TEST ONLY paper seed locally; record three observations.
Reopen the saved public map from the data USB and reconstruct a watch-only wallet.
Compare the complete policy and baseline addresses. Keep original records intact.
On Windows, confirm Testnet4 before opening the watch-only wallet. Match its full
receive address against the offline baseline, obtain matching test coins and
capture explicit confirmation before spending.

T7.3 TRY ALL THREE SIGNING PAIRS
Make a plan for A+B, A+C and B+C, leaving enough funds for later recovery spends.
Use a separate transaction for each pair; wait for verified confirmation before
spending its change. Do not sign three conflicting versions of the same input.
Use WALLET-TRANSFER-CHECKS.txt for output/fee review, files and warning handling.

For EACH pair:
a. Windows: prepare an unsigned PSBT; verify recipient, amount, fee and change.
   Save and reopen its USB copy (example: T7-Testnet4-AB-unsigned.psbt).
b. Fresh offline Tails, first key: load only that seed with the full public map
   (the other two keystores stay public-only). Compare policy and addresses.
   Review every output and total fee, then sign. Save a partially signed PSBT.
   Reopen that USB file and record which key signed and the incomplete state.
c. On the FIRST pair, record T7.4's one-key check NOW, before adding a second key.
d. Save evidence, eject and fully shut down. Fresh offline Tails, second key:
   restore that distinct seed plus the complete public map. Recheck policy,
   addresses and the same transaction; add the second signature.
e. EXPECT: two distinct required signatures for EVERY input. Save Final
   Transaction as .txn only when complete. Reopen its USB copy and recheck.
f. After full shutdown, Windows: select Testnet4 first, reopen the signed file
   inside Sparrow, review and broadcast once. Record explicit confirmation,
   block height and expected remaining balance without verification warnings.

Keep a separate result and evidence for AB, AC and BC. One successful pair or
an address match does not pass the other pairs. The total fee depends on the
actual multisig transaction; do not use the 110-sat T6 example as a T7 fee.

T7.4 ONE KEY CANNOT COMPLETE THE SPEND
Use the first pair's saved partial PSBT before the second signature. Check that
only one distinct required key has signed and the spend is incomplete. Capture
the incomplete-signature state or refusal message without broadcasting an
incomplete transaction. Record the actual behavior; a planned check is not PASS.
Then continue that same transaction with the second key. Do not add a redundant
spend just to repeat this checkpoint.

T7.5 RECOVER WITH ONE SEED UNAVAILABLE
Set C's paper seed aside; preserve it. Prepare a new recovery transaction online.
In fresh offline sessions, rebuild with the complete saved public map and paper
records A and B, one secret per boot, without the original signing wallet files.
Check all three public cosigners, policy, receive addresses and change. Sign with
A then B using the same saved/reopened partial-file flow. Broadcast online and
record verified confirmation. EXPECT: same wallet and a completed recovery spend.

T7.6 RECOVER WITH THE WORKING MAP COPY UNAVAILABLE
Preserve the original map for later comparison; withhold it during reconstruction.
Use all three paper seeds in THREE separate offline boots, one secret at a time,
and the recorded original script/account/derivation settings to recreate all
three public records. Never import all seeds into a combined saved wallet.
In a fresh seed-free session, rebuild the public configuration. EXPECT: the
same policy, all three origins/public keys, receive and change addresses as the
baseline. Record the reconstructed-map result separately from seed-loss recovery.
Use that reconstructed map with two paper-restored keys in separate sessions to
complete and confirm a new test spend. Keep enough balance for remaining work;
use Max only for the final planned spend after the handover plan is settled.
All three seeds help reconstruct public data; only two signatures are needed.
They do not guarantee recovery without the correct original setup information.

T7.7 HANDOVER, RESULTS AND CLOSEOUT
Have another reader follow the disposable records and inheritance instructions.
Record their result for each required recovery step and any missing or confusing
instruction. This remains a T7 requirement; T6's removal of another-reader work
does not remove it here. Keep secrets out of shared evidence.

Review the pair, single-key, both recovery and handover outcomes. Record the
expected final balance (zero only if the final payment used Max). Reopen saved
images and public result files from USB. Close/eject and shut down Tails fully.
Submit public evidence later from an online session. Preserve original test
records until review closes; never reuse them for real custody.
